# ExcelFiles — Calibration Data Inputs

This folder holds the Excel workbook(s) used to calibrate the DGE-METRIC model.
Each workbook is named after its sector/region count, e.g.:

```
ModelCalibration<S>Sectorsand<R>Regions.xlsx
ModelBaseline<S>Sectorsand<R>Regions.xlsx
ModelScenarios<S>Sectorsand<R>Regions.xlsx
```

(`RunSimulations.m` builds these filenames from the `sSubsecend`/`sRegions` macros at
runtime.) The older combined-workbook naming,
`ModelSimulationandCalibration<S>Sectorsand<R>Regions.xlsx`, is retained only under
`Archive/` and is not read by the current pipeline.

The active calibration workbook is the **single point of entry for calibration data**.  A MATLAB script
(`Functions/Miscellaneous/Excel/update_data_excel.m`) reads it and distributes values to all
scenario sheets automatically — you should never need to edit scenario sheets by hand.

## IO_Data sheet

### What it contains

A compact IO-table-style view of all per-sector calibration shares for **one region**.
Rows are subsectors; columns cover both the intermediate input matrix and the primary-input block.

| Column block | Parameters | Base |
|---|---|---|
| Cols C–G (5 × 5 matrix) | `phiQI_{using,supplying}` — intermediate input shares | share of Q₀ |
| Col H | `phiX` — exports | share of Q₀ |
| Col I | `phiM_I` — intermediate imports | share of Q₀ |
| Col J | `phiW` — labour compensation | share of Y₀ |
| Col K | `phiY0` — value added | share of Y₀ |
| Col L | `phiN0` — employment share | share of LF₀ |
| Row 10 | `phiM_F` — final/household imports | share of Q₀ |

Subsectors (rows 4–8): **Primary · Fossil · Renewables · Secondary · Tertiary**

Energy (Fossil + Renewables) appears as two separate rows.  The update script sums them
into the aggregate `Energy` index (k = 2) when writing the 3-index `phiQI` named ranges.

### Accounting identities to verify

For each subsector *s*:

```
phiQI_s  =  sum of row s across cols C–G        (row sum of intermediate matrix)
phiQ_s   =  phiQI_s + phiY0_s                   (gross output share)
```

The **Total** column in Trade_Flows should equal `phiX` in this sheet for each subsector.

### How to fill it in

1. Obtain an Input-Output table for the country/region (e.g. OECD ICIO, national
   statistical office).
2. If using the team's reproducible IO pipeline, use its generated 5-sector DGE
   output files (for example `IO_2019_5sec_for_DGE_IO_Data.xlsx/.csv`) as the
   direct source for this sheet.
3. Aggregate the IO table's industries to the five model subsectors using the OECD/ISIC
   mapping column D in the Trade_Flows sheet as a guide.
4. Normalise all cells by economy-wide gross output Q₀ (sum of all sector outputs).
5. Paste or type values directly into the coloured data cells (rows 4–8, row 10).
6. Run `update_data_excel.m` — it reads IO_Data and propagates values to all scenario sheets.

## Trade_Flows sheet

### What it contains

Bilateral export **destination shares**: for each (source subsector, source region) row,
what fraction of that subsector's total exports goes to each destination region.

```
Rows  :  Source Region  |  Aggregate Sector  |  Subsector
Cols  :  [one per explicitly modelled destination region]  |  ROW  |  Check
```

**Each row sums to 1.** The absolute bilateral flow is computed by
`update_data_excel.m` as `γ_{s,r,r2} × phiX_{s,r}` (share of Q₀) and written
to the named range `phiX_{srcSub}_{srcReg}_{dstReg}_p` in the Data sheet.

### Key columns

| Column | Content |
|---|---|
| Source Region | ISO code of source country/region (e.g. `VNM`) |
| Aggregate Sector | Aggregate sector label (e.g. `Energy`) |
| Subsector | Subsector name — must match IO_Data exactly |
| Destination region cols | Share of phiX going to that region (green, user input) |
| **ROW** | `= 1 − SUM(dest cols)` — residual share to Rest of World (formula) |
| **Check** | `= SUM(all cols incl. ROW)` — should show `1.0000`; flags data errors |

### How to populate from OECD ICIO / TiVA data

1. Download the OECD Inter-Country Input-Output (ICIO) table or TiVA bilateral trade data.
2. For the source country (e.g. VNM), sum exports to each destination country across
   ISIC Rev. 4 industries that map to each model subsector:

   | Model subsector | ISIC Rev. 4 industries |
   |---|---|
   | Primary | A01–A03, B05–B09 |
   | Energy (Fossil) | D35 fossil-fired (model-specific split) |
   | Energy (Renewables) | D35 renewable (model-specific split) |
   | Secondary | C10–C33, F41–F43 |
   | Tertiary | G45–U99 |

3. For each (source subsector, destination region) pair, compute the share:
   `exports to dest_r2 / total exports of subsector s` — this gives the
   destination share γ ∈ [0,1] that belongs in the table.
4. Enter values in the green destination-region cells.
   The ROW and Check columns recalculate automatically.
5. Verify the Check column shows `1.0000` for every row before running the update script.
6. Run `update_data_excel.m`.

> **Note:** `phiX_{s,r}` (total exports as share of Q₀) is read from IO_Data, not
> from this sheet.  You only enter where exports go, not how large they are.

### Adding more destination regions

1. Insert a new column between the last destination-region column and the ROW column.
2. Enter the ISO code of the new region as the column header in row 2.
3. Enter bilateral destination shares in the data rows (green cells).
4. The ROW formula auto-adjusts; verify the Check column.
5. Run `update_data_excel.m` — no MATLAB code changes needed.
   The script auto-detects destination regions from the header row.

## Running the update script

```matlab
% In MATLAB, from the repo root:
run('Functions/Miscellaneous/Excel/update_data_excel.m')
```

The script runs in three stages:

1. **IO_Data → Data** — reads intermediate input matrix, export/import/labour/VA/employment
   shares and writes them to named ranges in Data.
2. **Trade_Flows → Data** — reads bilateral destination shares (rows sum to 1), multiplies
   by `phiX_{s,r}` from IO_Data, and writes `phiX_{s,r,r2}_p` named ranges to Data.
3. **Data → all scenario sheets** — two-pass propagation.  Pass 1 writes values and saves;
   Pass 2 reopens so Excel recalculates formula-driven Data cells before re-propagating.
   Any sheet with `Parameter` / `Value` headers in row 1 is updated automatically.

Between stages 1 and 2, consistency checks are printed to the MATLAB command window
(warnings flagged with `WARN`; a summary is shown before propagation begins).

## Updating the Baseline workbook

The model reads the runnable baseline path from:

```matlab
ExcelFiles/ModelBaseline5Sectorsand1Regions.xlsx
```

The split baseline workbook now separates editable assumptions from the hardcoded
model input:

| Sheet | Purpose |
|---|---|
| `Baseline_Input` | User-edited annual assumptions and scenario controls |
| `Baseline_calc` | Formula helper sheet |
| `Baseline_Implied` | Formula-driven model-ready baseline scenario |
| `Baseline` | Values-only hardcoded copy read by MATLAB/Dynare |

After editing `Baseline_Input`, refresh the hardcoded `Baseline` sheet from MATLAB
at the repository root:

```matlab
run('scripts/maintenance/update_baseline_sheet.m')
```

This recalculates the split workbook, copies `Baseline_Implied` values into
`Baseline`, validates that `Baseline` has sequential `Time` values and no duplicate
headers, and verifies that `Baseline` is formula-free. If `Baseline_Implied` is
missing, the helper bootstraps the split workbook from the legacy combined workbook
once.

After a baseline model run, `simulation_model_refactored.m` writes audit CSVs next to
`ExcelFiles/Output/Baseline.csv`. The sector audit compares each Excel `gY_s_r`
target with simulated real `Y_s_r` growth and simulated price-weighted
`P_s_r * Y_s_r` growth in the model numeraire. With the default `YTarget = 1`,
the price-weighted value-added growth is the target; real growth can differ when
sector relative prices or shadow values move.

### Troubleshooting

| Symptom | Likely cause |
|---|---|
| Script errors on open | Excel file is already open — close it first |
| Named range not found | Parameter exists in IO_Data but not yet in Data Name Manager — add it manually or extend the named-range block in Data |
| ROW column shows negative | Destination cells sum to more than Total (phiX) — check normalisation |
| Import total mismatch | Trade_Flows column sums don't match `phiM_I + phiM_F` in IO_Data — reconcile sources |

## Parameter naming convention

Named ranges in the **Data** sheet use numeric indices (not sector names):

```
phiX_s_r_p          export share,  subsector s, region r
phiM_I_s_r_p        intermediate import share
phiM_F_s_r_p        final import share
phiW_s_r_p          labour compensation share
phiY0_s_r_p         value added share
phiN0_s_r_p         employment share
phiQI_s_r_p         total intermediate input share  (2-index)
phiQI_s_r_k_p       intermediate input from aggregate sector k  (3-index)
phiX_s_r_r2_p        bilateral export: absolute share of Q0 from (s,r) to region r2  (3-index)
                     value = gamma_{s,r,r2} * phiX_{s,r}  where gamma is the Trade_Flows destination share
```

Index mapping (current 5-subsector, 1-region configuration):

| Index | Subsector | | Index | Aggregate supply sector |
|---|---|---|---|---|
| 1 | Primary | | 1 | Primary |
| 2 | Fossil | | 2 | Energy (Fossil + Renewables) |
| 3 | Renewables | | 3 | Secondary |
| 4 | Secondary | | 4 | Tertiary |
| 5 | Tertiary | | | |
